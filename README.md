# Balloons Detector Main

Локальная веб-панель для обнаружения воздушных шариков и наведения камеры на выбранную цель через **SimpleBGC Serial API**.

**Стек:** Python · YOLOv8 / PyTorch · OpenCV · FastAPI · JavaScript.
Проверенная установка: USB/UVC-камера AR0234, ноутбук Windows с NVIDIA RTX 3060 Laptop,
SimpleBGC v3 с прошивкой 2.70b0, моторы GM6208. Моторы управляются настроенной платой, а не напрямую из Python.

## Возможности

- Детекция шариков разных цветов; отображение только при уверенности **≥ 0.35**.
- Подтверждение цели по трём последовательным кадрам и сопровождение выбранного ID.
- Управление Pitch/Yaw, ограничения углов и скорости, разгон и прогнозное торможение.
- Подключение COM-порта, телеметрия, включение/выключение моторов и симуляция контроллера.
- Масштабирование видео **1×–8×**, перемещение увеличенного кадра, точный выбор цели.
- Калибровка смещения лазера относительно камеры; голубой прицел с незакрашенным центром.
- Остановка при потере цели, устаревшем кадре, потере связи или heartbeat интерфейса.

## Быстрый запуск — Windows / PowerShell

Требуются Git, Python для запуска установщика и доступ в интернет при установке.
`setup.ps1` создаёт Python 3.12 и устанавливает закреплённые зависимости, включая PyTorch CUDA 12.8.
Для GPU нужен совместимый драйвер NVIDIA; при отсутствии CUDA приложение выбирает CPU, скорость будет ниже.

```powershell
git clone https://github.com/smifick/Balloons_Detector_Main.git
cd Balloons_Detector_Main
.\setup.ps1
.\.venv\Scripts\python.exe web_app.py
```

Откройте **http://127.0.0.1:8787/**. Обученные веса `models/balloon.pt` включены в репозиторий;
перед первым запуском обучение не требуется. Альтернатива запуска: `./start_panel.ps1`.

1. Освободите камеру от других приложений и запустите видеопоток.
2. Выберите COM-порт контроллера и подключитесь либо включите симуляцию.
3. Проверьте направления осей, пределы, питание моторов и калибровку на вашей установке.
4. Выберите шарик по рамке или карточке, затем нажмите «Начать наведение».
5. Для остановки используйте кнопку, **Space** или **Esc**. Остановка наведения сохраняет питание моторов.

Колесо мыши приближает область около курсора. Перетаскивание перемещает увеличенный кадр;
«Весь кадр» сбрасывает масштаб. Для совмещения прицела используйте «Указать пятно лазера в видео».

Подробности: [инструкция панели](control_panel/README.md).

## Настройки и ограничения

`panel_settings.json` создаётся локально и не публикуется: угловые пределы, инверсия осей и поправка
лазера относятся к конкретной сборке. Исходные значения программы: 6°/с, Pitch ±30°, Yaw ±45°,
зона покоя 7 px, прогноз торможения 0.28 с. Пределы отсчитываются от положения при подключении.
Программа не выполняет автоматическую настройку PID моторов или калибровку IMU.

`camera_config.json` задаёт камеру 0, захват 640×480 и размер инференса 640.
HD-режимы этой камеры давали только 4–9 кадров/с, поэтому они не включены по умолчанию.
`camera_exclusions.json` содержит область колпачка конкретной установки: при другой геометрии
её нужно перенастроить. В этой области могут отбрасываться и настоящие шарики.

Сервер доступен только локально, команды требуют токен страницы. После запуска наведение выключено.
При потере выбранного ID приложение не переключается автоматически на другой шарик.
Симуляция проверяет команды контроллера, но не моделирует движение изображения.

Постоянное смещение физического пятна требует калибровки на рабочей дистанции: прогноз торможения
не исправляет параллакс. Точное совмещение физического пятна после последних изменений ещё не подтверждено.

## Модель и обучение

Включена модель с адаптацией к маленькому светло-зелёному шарику. На исходной проверочной выборке
из 13 изображений: **mAP@50 = 0.8217**, **mAP@50–95 = 0.6718** (NMS IoU 0.4).
Эта выборка использовалась при выборе модели; независимого теста по всем цветам нет.
Кадры комнаты, пользовательские видео, датасеты и промежуточные веса не публикуются.

- [Карточка активной модели](models/README.md)
- [История данных и обучения](docs/TRAINING.md)
- [Структура проекта и разработка](docs/DEVELOPMENT.md)

Для базового обучения на открытом наборе Matterport:

```powershell
.\.venv\Scripts\python.exe download_dataset.py
.\.venv\Scripts\python.exe prepare_dataset.py
.\.venv\Scripts\python.exe train.py
```

Результат записывается в `runs/balloon_yolov8n/weights/best.pt`; активную модель он автоматически не заменяет.
Скрипты `adapt_*.py` относятся к локальным экспериментам и требуют исходных кадров с соответствующей разметкой.

## Проверки

```powershell
.\.venv\Scripts\python.exe -m pytest tests -q
node --test tests/test_video_view.cjs
```

Python-тесты проверяют протокол, ограничения, потерю связи/цели, торможение и API.
JavaScript-тесты проверяют преобразование координат при увеличении и перемещении видео.
Они не требуют подключённого подвеса. Аппаратные проверки точности выполняются отдельно.
