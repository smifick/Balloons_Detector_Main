# Локальная панель наведения

Запуск из корня проекта:

```powershell
.\.venv\Scripts\python.exe web_app.py
```

Панель: [http://127.0.0.1:8787](http://127.0.0.1:8787).
Сервер и детектор работают на ноутбуке; доступ к COM-порту выполняется сервером.
Для запуска также есть `start_panel.ps1`. Камеру нужно освободить от `detect.py` и других приложений.
Если окружение устанавливается заново, `setup.ps1` устанавливает зафиксированные зависимости.

## Работа

1. Дождитесь видео. Шарик появляется в списке после трёх последовательных обнаружений с уверенностью ≥0.35.
2. Выберите COM-порт и подключите контроллер. USB-UART CP210x предлагается первым.
3. Проверьте отображённую платой версию прошивки. При проверке оборудования здесь COM9 сообщил плату 3.0 и прошивку 2.70b0.
4. Выберите шарик кликом по рамке или карточке под видео.
5. Нажмите «Начать наведение». Камера поворачивается по Pitch/Yaw, уменьшая отклонение центра выбранной рамки от откалиброванной точки прицеливания.
6. Для остановки нажмите красную кнопку, Space или Esc. Выбор другого шарика также останавливает текущее наведение.

Скорость ограничена по умолчанию 6°/с. Чувствительность задаёт скорость при отклонении на половину ширины/высоты кадра.
Зона покоя по умолчанию 7 px. Инверсии Pitch/Yaw позволяют согласовать направление с установкой осей.
«Проверка направления» даёт импульс 0.2 с со скоростью до 3°/с; проверку можно выполнить без выбранной цели.
Изменение настроек останавливает наведение. Порог уверенности нельзя опустить ниже 0.35.

Режим «Симуляция» проверяет команды и состояния интерфейса без COM-порта и движения моторов.
Видео в этом режиме остаётся реальным. Симулятор не моделирует изменение изображения от поворота подвеса.

## SimpleBGC и GM6208

Реализован совместимый набор [официального Serial API](https://www.basecamelectronics.com/serialapi/):

- `BOARD_INFO` (#86): сведения о плате и прошивке;
- `GET_ANGLES` (#73): телеметрия Roll/Pitch/Yaw;
- `CONTROL_CONFIG` (#90): подтверждаемый платой тайм-аут 500 ms и сглаживание команд;
- `CONTROL` (#67): отдельные режимы осей, Roll — обычное управление, Pitch/Yaw — скорость.

Протокол 2 с CRC16 используется по умолчанию. Формат CRC проверен по контрольному примеру из спецификации.
Для 2.70b0 не используются MODE_IGNORE, TARGET_PRECISE, современные jerk/servo-режимы и другие поля последующих прошивок.
Перед первым движением требуется подтверждение CONTROL_CONFIG. Частота команд — до 50 Hz.
Скорость кодируется в единицах 0.1220740379°/с, углы читаются в единицах 360/16384°.

GM6208 управляются через настроенный контроллер. Панель не определяет тип подключённых моторов и не настраивает
их мощность, число полюсов, PID стабилизации, калибровку IMU или прошивку. Эти параметры остаются задачей BaseCam GUI.

## Остановка и пределы

«Стоп» задаёт нулевые скорости Pitch/Yaw; питание моторов сохраняется. При пропуске выбранной цели движение
сразу останавливается. В течение 0.6 с допускается повторное подтверждение того же ID; после удаления ID
наведение отключается и нужно выбрать цель заново. Автоматического перехода на другой шарик нет.

Если кадр старше 0.2 с, нет свежей телеметрии, окно управления отключилось или перестал приходить heartbeat,
сервер прекращает наведение. При полном прекращении отправки команд тайм-аут платы завершает serial control;
затем плата возвращается к обычному RC/Follow-поведению согласно её настройкам.

Программные пределы по умолчанию: Pitch ±30°, Yaw ±45° относительно положения при подключении.
При подтверждённом переходе моторов из OFF в ON ноль обновляется по положению после включения.
Повторная команда ON при уже включённых моторах и повторный запуск наведения ноль не меняют.
Когда ограничитель уменьшает команду поворота, статус показывает ось, её отклонение и действующий предел;
жёлтый статус отличает эту ситуацию от достижения центра цели.
Yaw разворачивается через границу углов без скачка. Кнопка «Принять положение за 0°» меняет только
начало программных ограничений; она не калибрует IMU и не перемещает подвес.
Пределы относятся к углам IMU и не являются измерением механических пределов шарниров.

Сервер слушает только 127.0.0.1. Команды изменения состояния требуют токен страницы; сторонним сайтам
не разрешено отправлять команды панели. После перезапуска наведение всегда выключено.

## Скорость следования

### Приближение видео для точного выбора

Колесо мыши над видео увеличивает/уменьшает область вокруг курсора (1×–8×).
Кнопки «+» и «−» под видео меняют масштаб вокруг центра видимой области.
При увеличении перетаскивайте кадр левой кнопкой мыши; отпускание после перетаскивания
не выбирает цель и не сохраняет калибровку. «Весь кадр» возвращает масштаб 1×.
Клик по шарику и по пятну при калибровке пересчитывается в координаты исходного кадра,
включая полноэкранный режим с полями по краям. Это увеличение изображения для отображения;
геометрия наведения и сохранённая поправка лазера не меняются.

Проверка преобразования координат: `node --test tests/test_video_view.cjs`.

Заданная максимальная скорость используется при большом отклонении цели. Нелинейная кривая
`max_speed * tanh(gain * (abs(error) - deadband) / half_frame)` плавно уменьшает скорость
только при приближении к зоне покоя; внутри зоны покоя требуемая скорость равна нулю.
Чувствительность X/Y задаёт ширину области торможения: большее значение сужает её.
Параметр «Разгон» ограничивает только увеличение модуля скорости. При приближении к цели
команда уменьшается без задержки разгона; при смене знака ошибки сначала отправляется ноль,
затем начинается разгон в обратную сторону. В зоне покоя команда сразу нулевая.
Фактическое торможение также зависит от внутренних настроек SimpleBGC и механики.
Программные угловые пределы сохраняют приоритет.
Например, при 640×480, 30°/с, чувствительности X=16 и зоне покоя 7 px отклонение 100 px
по X даёт почти 30°/с вместо прежних 5°/с, а 20 px — около 17°/с вместо 1°/с.
Это расчёт команды, фактическая скорость также зависит от настроек и нагрузки подвеса.

Предторможение использует скорость сближения цели с откалиброванной точкой прицеливания,
измеренную по новым видеокадрам. Повторные тики управления одного кадра не считаются
новыми измерениями. Скорость оценивается с фильтрацией; при смене цели и потере изображения
история сбрасывается. Прогноз может заранее снизить команду до нуля, но не разворачивает
ось до фактического перехода цели через прицел. Начальное значение — 0.28 с;
параметр в панели допускает диапазон 0–0.35 с. Ноль отключает прогноз.
Цифры ошибки X/Y отсчитываются от прицела с учётом поправки лазера, а не от центра камеры.
Прогноз уменьшает перелёты при подходе; постоянное несовпадение неподвижного пятна
с прицелом требует калибровки на соответствующей рабочей дистанции.

## Проверка и диагностика

### Совмещение лазера с камерой

В параметрах откройте «Совмещение лазера с камерой». На рабочей дистанции нажмите
«Указать пятно лазера в видео» и кликните по фактическому пятну. Вход в этот режим
останавливает наведение. Клик сохраняет положение пятна относительно центра кадра
в процентах ширины/высоты (`aim_x_percent`, `aim_y_percent`); это сохраняет направление
поправки при смене разрешения с тем же полем зрения. Поправка применяется при следующем
ручном запуске наведения. Основной прицел показывает откалиброванную точку,
серый крест — геометрический центр камеры. Сброс возвращает оба смещения в ноль.
При сохранении поправки остальные параметры, в том числе угловые пределы, сохраняются.

Калибровка действует для дистанции, на которой указано пятно. При разнесённых камере
и лазере параллакс зависит от расстояния. В режиме видео нельзя точно определить
поправку по отдельной фотографии без координат пятна в исходном кадре.

```powershell
.\.venv\Scripts\python.exe -m pytest tests/test_control_panel.py -q
```

Проверяются CRC/пакеты, порядок осей, подтверждение тайм-аута, ограничения скорости и углов,
потеря цели/камеры/связи, остановка, отсутствие самопроизвольного переключения цели и API.
На настоящей плате COM9 проверены версия 3.0 / 2.70b0, чтение телеметрии, управление
моторами и наведение. Автоматические тесты используют симулятор и не подтверждают
точность физического лазерного пятна. После изменений механики нужна повторная калибровка.

Логи сервера — `panel_server.log`, текущие настройки — `panel_settings.json`.
Журнал событий и ошибки камеры/контроллера доступны в самой панели.

## Кнопка питания моторов

В блоке «КОНТРОЛЛЕР» добавлена кнопка «Включить моторы» / «Выключить моторы».
Состояние читается из REALTIME_DATA_3 (#23), бит 0 RT_DATA_FLAGS; обновление каждые 0.5 с.
Команды MOTORS_ON (#77) / MOTORS_OFF (#109) требуют подтверждения и проверки фактического состояния.
В 2.70b0 выключение использует safe stop (mode 2). Перед переключением наведение останавливается;
включение моторов не возобновляет его автоматически. При выключенных моторах запуск наведения и импульсы направлений недоступны.
Изменение состояния и ошибки подтверждения проверены в симуляторе и тестах протокола.
